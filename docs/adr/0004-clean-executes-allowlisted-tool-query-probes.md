# Clean resolves Review suggestion paths with allowlisted tool probes

`foal clean --dry-run` (and the Clean TUI) may execute a small, built-in allowlist of developer tools using only their read-only query subcommands (for example `npm config get cache`, `go env GOCACHE`, `dotnet nuget locals all --list`, and `mise cache path`) to resolve the cache path shown in a Review suggestion. This is the one deliberate exception to Clean's otherwise execution-free preview. Each query probe is gated by `exec.LookPath` (only installed tools are spawned), is restricted to non-mutating query subcommands, never runs a tool's cleanup command, and is bounded by a per-call context timeout (2s). Probes never run during `foal clean --execute`.

We chose this because Review suggestions point users at an external tool's own cleanup command, and the most accurate displayed path comes from asking the tool itself — config-file customizations (e.g. `.npmrc`) are invisible to environment-variable and default-path resolution. The suggested command stays correct regardless of the resolved path, so the probe buys display accuracy and existence-gating, not authorization.

Corepack is the narrow environment/default resolution exception. Corepack v0.35.0 exposes `corepack cache clean` and `corepack cache clear`, but no read-only cache-path query. Foal still gates the suggestion on `corepack` being present on PATH, then mirrors Corepack's official v0.35.0 path rule without spawning it: use `COREPACK_HOME` when set; otherwise use `XDG_CACHE_HOME`, then `LOCALAPPDATA`, then the platform-specific user-home cache base; append `node/corepack` for fallback bases and finally append the install-folder version `v1`. Foal suggests `corepack cache clean` only when that resolved directory exists. This exception is based on Corepack's [`folderUtils.ts`](https://github.com/nodejs/corepack/blob/v0.35.0/sources/folderUtils.ts) and [`Cache.ts`](https://github.com/nodejs/corepack/blob/v0.35.0/sources/commands/Cache.ts).

Bun is a second, narrower exception: Dry-run still prefers the allowlisted read-only query `bun pm cache` for config-aware Review display, but that query is CWD-sensitive and fails outside a Bun project (`No package.json was found for directory`). When the query fails, times out, or yields no usable existing path, Review discovery falls back to Bun's official environment/default roots — non-empty `BUN_INSTALL_CACHE_DIR`, otherwise the current user's `.bun\install\cache` — only when `bun` is on PATH and the fallback root exists. This fallback reuses the same env/default resolver used by the `bun-cache` Opt-in category; it never runs `bun pm cache rm` or any Bun cleanup command, and probes still never run during `foal clean --execute`.

## Considered options

- **Pure env + default-path resolution for every tool** — rejected: preserves the no-execution and no-timeout posture but misses tool-config-customized cache paths. It is accepted only for Corepack because Corepack has no supported read-only path query and publishes a narrow official path rule, and as a Dry-run fallback for Bun when the CWD-sensitive query is unusable.
- **Unbounded execution of any matching PATH binary, no timeout (Mole's native style)** — rejected: a hijacked `npm`/`pip` on PATH would run during a read-only preview, and a wedged tool could hang `foal clean --dry-run` indefinitely. Mole itself wraps every such call in `run_with_timeout` for exactly this reason.
- **Drop Bun Review when `bun pm cache` fails outside a project** — rejected: hides a high-value official global cache solely because Foal's working directory lacks `package.json`, even though Bun documents `~/.bun/install/cache` / `BUN_INSTALL_CACHE_DIR` as the global install cache.

## Consequences

This reverses two prior postures: Clean previously executed no third-party binaries during scanning, and `CONTEXT.md` deliberately avoided wall-clock timeouts for opportunity inspection (a deterministic descendant-count ceiling was chosen instead). Those decisions still hold for filesystem inspection; this ADR scopes execution narrowly to allowlisted, query-only, timeout-bounded probes used solely for Review suggestion paths. A future "Clean must never execute anything" hardening pass would have to remove tool-queried paths and fall back to env/default resolution — treat each probe as an intentional, bounded exception, not an oversight.

The allowlist is an execution surface for every tool except Corepack. Any other addition must ship with both a supported read-only query subcommand and a native cleanup command, or it does not belong here. Corepack's environment/default resolver is not precedent for inferred paths for other tools; Bun's env/default fallback is limited to compensating for CWD-sensitive query failure and still prefers a successful probe. Changing or adding such an exception requires another explicit ADR decision.
