# Clean may delegate Windows component servicing with disclosed elevation

Foal will add stable catalog action `invoke_windows_servicing` for component-store cleanup, with action-specific UAC consent and contracts, rather than deleting files beneath `WinSxS`. This expands Clean's Planned action vocabulary beyond the two deletion actions while keeping action ownership at the private canonical category registration point. Windows servicing owns component selection and mutation; Foal may orchestrate, confirm, cancel when supported, and report the servicing operation, but DISM analysis is not a file-candidate manifest and must never be converted into Recycle Bin or Permanent deletion paths.

Elevation uses an isolated helper of the same Foal executable. The coordinating process remains non-elevated and launches the helper only after confirmation; the helper accepts a fixed built-in servicing capability, never an arbitrary executable, command line, or path. Ordinary Recycle Bin and Permanent deletion stay in the non-elevated coordinator. UAC denial or helper failure skips or fails only the servicing action, while unrelated safe work continues. This narrowly supersedes ADR 0019's non-executable WinSxS decision and ADR 0028's Uninstall-only elevation rule; system paths remain protected from Foal-owned deletion.

The first capability permits only `DISM /Online /Cleanup-Image /AnalyzeComponentStore` for analysis and `DISM /Online /Cleanup-Image /StartComponentCleanup` for confirmed execution. `/ResetBase`, `/SPSuperseded`, `/Remove-Package`, user-supplied DISM arguments, and direct deletion anywhere beneath `WinSxS` are excluded. Supporting any additional servicing operation requires a separate decision and capability rather than widening this helper's command surface.

Default Clean Dry-run and entry into the Clean TUI never request elevation. An exact CLI opt-in may request UAC to analyze this category, while the TUI requires a distinct category-scoped analysis action; the row starts unselected and cannot become selectable until analysis succeeds. UAC denial yields a stable path-free skip with no guessed bytes and does not affect other categories. Analysis consent is per invocation and is not reused as execution consent; confirmed execution performs its own UAC request.

Both analysis and execution use fixed `/Online /English /NoRestart` DISM invocations. Fresh execution first runs `AnalyzeComponentStore` and proceeds only when DISM exits successfully, `Number of Reclaimable Packages` parses to a positive value, and `Component Store Cleanup Recommended` parses as `Yes`. Non-zero exit or missing/unknown fields fail before mutation; zero packages or `No` yields `no_work`. The category reports package count and recommendation only: component-store overhead and Explorer size are not reclaimable-byte estimates and never enter Clean byte totals. Only a passing preflight may invoke `StartComponentCleanup`.

Cancellation is cooperative only before `StartComponentCleanup` begins. After DISM starts mutation, Foal records that cancellation was requested, starts no later work, does not terminate DISM, TrustedInstaller, or the elevated helper, and remains attached until Windows returns. The category's final result follows the actual DISM exit outcome (`completed` or `failed`) rather than claiming rollback or a safely canceled servicing transaction.

Mixed Clean execution completes ordinary preflight, then runs Recycle Bin actions, Permanent deletion, and Windows servicing in that order. Servicing is always last; once it begins no later category may start. UAC denial or servicing failure does not roll back completed ordinary actions, and Result/History preserve the partial run. Confirmation discloses that the servicing UAC prompt may appear after ordinary cleanup has completed.

CLI mutation requires `--execute`, selection of the servicing category, dedicated per-run `--allow-servicing`, and successful UAC consent. `--allow-permanent` and `--allow-servicing` are independent and never imply one another. Missing servicing authorization skips with stable reason `windows_servicing_not_authorized` and never opens UAC, including runs that selected the category through `all`. Explicit Dry-run analysis remains non-mutating and does not require this mutation authorization. The Clean TUI confirmation supplies equivalent authorization only for an explicitly analyzed and selected servicing category.

Result and History represent servicing through dedicated path-free, byte-free operation records. Servicing never enters file `candidates`, `opt_in_candidates`, `deleted`, `failed`, or item-level path History, and never contributes to candidate, affected, Recycle Bin, or Permanent deletion bytes. Aggregate contracts add servicing counts only. Each servicing record carries category, planned action, fixed capability, parsed analysis evidence, outcome, cancellation-request state, and a stable reason when applicable; it never invents a WinSxS path or byte estimate.

Servicing outcomes are stable values `ready`, `no_work`, `completed`, `skipped`, `failed`, and `canceled`; `canceled` applies only before mutation begins. Stable reasons are `windows_servicing_not_authorized`, `windows_servicing_elevation_denied`, `windows_servicing_elevation_failed`, `windows_servicing_tool_unavailable`, `windows_servicing_helper_failed`, `windows_servicing_analysis_failed`, `windows_servicing_analysis_output_invalid`, `windows_servicing_cleanup_failed`, `context_canceled`, and `unsupported_platform`. An optional exit code is present only when DISM actually ran to exit. Post-start cancellation sets `cancel_requested` while preserving the actual completed or failed outcome. CLI, TUI, JSON, and History share this vocabulary.

DISM stdout, stderr, package identifiers, and raw error text are bounded in memory for parsing only and are never returned or persisted in Result, History, TUI, detailed lists, or helper IPC. External surfaces use Foal-owned stable messages plus parsed analysis fields and an optional exit code. Failure guidance may direct the user to Windows DISM/CBS logs but does not copy their content or path-bearing details into Foal records.

Coordinator/helper IPC uses a one-request, versioned Windows named pipe rather than a temporary request file. The pipe has a random one-time nonce and an ACL restricted to the invoking user and administrators; both peers validate process identity and the same Foal executable before accepting data. Requests contain only protocol version and a built-in servicing capability enum—never an executable, command line, DISM arguments, or path—and cannot be replayed. Protocol mismatch, direct unauthenticated helper invocation, peer validation failure, or timeout fails closed. The response is the structured servicing operation record only.

The only capabilities are read-only `analyze_component_store` and composite `execute_component_store_cleanup`. The composite capability performs fresh `AnalyzeComponentStore`, parses and enforces the guard, and only then invokes `StartComponentCleanup` inside the same elevated helper and UAC transaction. There is no standalone `start_component_cleanup` capability, so neither the coordinator nor a direct helper invocation can assert that analysis already passed or create an inter-process analysis-to-mutation gap.

The canonical category `winsxs_component_store` is exact-selection-only. It is not expanded by `all`, `dev-caches`, `app-caches`, `cli-agents`, or TUI Select All; no single-member servicing group is introduced. CLI must name the category exactly, while the TUI requires its individual analysis and selection flow. This deliberate exception prevents broad cleanup automation from implicitly requesting UAC or mutating Windows servicing state.

Path-based Protection is `not_applicable` to `invoke_windows_servicing`: Windows servicing does not disclose a Foal candidate path set, and inventing `C:\Windows` or `WinSxS` as a candidate would both misstate the mutation boundary and collide with built-in system-path protection. `pathsafe` continues to forbid Foal-owned deletion beneath Windows, and the helper cannot access deletion adapters. Exact selection, servicing authorization, confirmation, UAC, and fixed capability form the action-level safety boundary. A future persistent servicing deny policy must be designed separately rather than overloading path Protection.

Every DISM call uses `/NoRestart`; Foal never initiates a reboot or creates a reboot reminder. Servicing records carry `restart_required`. Exit code `0` is completed without a restart requirement; Win32 `3010` is completed with restart required; `3017` is failed with restart required; other non-zero exits are failed without inferring a restart requirement. CLI/TUI disclose the flag and History preserves it.

Foal uses a global named mutex to prevent concurrent Foal servicing helpers, but it does not infer Windows servicing idleness from `TrustedInstaller.exe`, `TiWorker.exe`, `dism.exe`, Windows Update, or BITS process presence. It never stops those processes or services, clears pending operations, renames servicing directories, or retries automatically. CBS/DISM owns system transaction serialization; lock, pending-operation, or servicing-conflict failures map to the existing stable analysis/cleanup failure reasons, after which the user may finish Windows Update or restart and preview again.

Only UAC/named-pipe connection establishment has a bounded timeout (initially two minutes) plus peer liveness checks. DISM analysis and cleanup have no forced wall-clock timeout. Pre-mutation analysis may be terminated on user cancellation and records `canceled`; after cleanup begins Foal waits without killing DISM or the helper. UI progress reports phase and elapsed time only, never a fabricated percentage. Helper crash or pipe loss maps to `windows_servicing_helper_failed` without claiming Windows rolled back.

The Clean TUI row starts unselected with state `analysis_required` and unknown bytes. Space cannot select it until the user invokes a distinct category-scoped analysis action (`a`) and receives `ready`; Select All never includes it. Analysis states are `analysis_required`, `analyzing`, `ready`, `no_work`, `skipped`, and `failed`. No-work is not selectable; denied, canceled, or failed analysis may be retried only through another explicit analysis action. Confirmation shows parsed package count, unknown bytes, servicing/UAC impact, and the post-start non-interruptible warning. Execute still performs its own fresh composite analysis.

The helper resolves `dism.exe` only from the Windows system directory obtained through Windows APIs, validates an ordinary non-reparse file identity before and after opening, and launches it directly with fixed argument arrays. PATH lookup, `%WINDIR%` or other environment overrides, CWD fallback, custom tool paths, `cmd.exe`, PowerShell, and shell command strings are forbidden. Unsupported platforms and unavailable or unverifiable system DISM map to their existing stable reasons.
