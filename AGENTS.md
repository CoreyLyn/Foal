## Product identity

- The project name is **Foal**.
- The CLI command name is `foal`.
- This is a pre-release hard rename: do not add legacy command aliases, config compatibility, or history compatibility unless explicitly requested.
- User-facing docs, help text, examples, build outputs, and command paths should prefer `Foal`, `foal`, and `foal.exe`.

## Product boundaries

Foal is a safe, preview-first cleanup CLI for Windows. It is inspired by tools like Mole, but it is not "Mole for Windows" and should not chase feature parity by default.

- Build Windows-native behavior around Windows risk: protected paths, Recycle Bin behavior, reparse points, UAC, installers, package managers, and JSON-first automation.
- Keep default cleanup rules conservative. More aggressive or high-disagreement rules must require explicit opt-in.
- Current execution is mixed-action capable. The complete permanent matrix is activated: `d3d_shader_cache`, `nvidia_dx_cache`, `amd_gpu_shader_caches`, `intel_gpu_shader_cache`, `browser_cache`, `vscode_cache`, `cursor_cache`, `vscode_insiders_cache`, `vscodium_cache`, `windsurf_cache`, `trae_cache`, package/build caches (`npm-cache`, `pnpm-cache`, `yarn-cache`, `go-cache`, `go-modcache`, `pip-cache`, `cargo-cache`, `nuget-cache`, `nuget-global-packages`, `corepack-cache`, `uv-cache`, `bun-cache`), `playwright-browsers`, `puppeteer-browsers`, `electron-cache`, `jetbrains-ide-caches`, `visual-studio-caches`, `grok-build-update-residue`, and `obsidian_cache`. Recycle Bin matrix categories (`user_temp`, `crash_dumps`, `windows_error_reporting`, exact-allowlist `explorer_thumbnail_cache` and `inet_cache`) and the default `foal_owned_temp_sandboxes` remain Recycle Bin. Permanent deletion is never a Recycle Bin fallback and requires per-run authorization (CLI `--allow-permanent` or TUI confirmation). Canonical matrix: `docs/plan/clean-deletion-policy.md`.
- Do not add automatic elevation. Permission failures should be reported as skipped items with clear reasons.
- `uninstall` supports Official uninstaller invocation for selected traditional desktop apps via `--execute --select <name>`; dry-run remains the default. Process stopping requires a separate `--allow-stop-processes` flag (default off). After a successful official uninstaller, Foal deletes only the revalidated subset of the Confirmed leftover path set (high-confidence Possible leftovers) via the Recycle Bin; failed or canceled uninstallers delete nothing. Portable directory removal and TUI multi-select are not in this slice.
- `optimize` is not in the current implementation scope. Future optimize work starts as read-only health checks and recommendations.
- The TUI remains read-only for non-Clean commands. Clean may orchestrate explicitly selected and confirmed cleanup through shared command/core execution paths, but the TUI must not own candidate resolution, deletion, uninstall, process stopping, elevation, or path-safety logic.

## Clean deletion policy (implemented)

- Every executable canonical cleanup rule must explicitly declare `move_to_recycle_bin` or `delete_permanently`; missing or unknown actions must fail registration. See `docs/plan/clean-deletion-policy.md` for the complete matrix (30 permanent + 6 Recycle Bin + one non-executable permission boundary).
- CLI and TUI must use the same category action. CLI permanent execution requires per-run `--allow-permanent`; dry-run does not. The TUI obtains equivalent authorization from one strengthened confirmation and never owns or overrides the action.
- Permanent matrix: `d3d_shader_cache`, `nvidia_dx_cache`, `amd_gpu_shader_caches`, `intel_gpu_shader_cache`, `browser_cache`, `vscode_cache`, `cursor_cache`, `vscode_insiders_cache`, `vscodium_cache`, `windsurf_cache`, `trae_cache`, package/build caches (including `pnpm-cache`, `yarn-cache`, and `go-modcache`), `playwright-browsers`, `puppeteer-browsers`, `electron-cache`, `jetbrains-ide-caches`, `visual-studio-caches`, `grok-build-update-residue`, and `obsidian_cache`. Recycle Bin matrix: `foal_owned_temp_sandboxes`, `user_temp`, `crash_dumps`, `windows_error_reporting`, `explorer_thumbnail_cache`, and `inet_cache`. The Clean TUI initially selects the default plus all permanent-action categories when safely measurable (31 rows). Recycle Bin opt-ins remain unselected, and the user may clear any selection.
- Shared Clean must complete fresh resolution and applicable preflight before mutation, execute Recycle Bin work first and permanent work last, isolate local failures, preserve actual action in Result and History, and support responsive cancellation without rollback.
- Do not add implicit permanent deletion, Recycle Bin failure fallback, secure-erasure claims, automatic elevation, process stopping, or permanent deletion for the six Recycle Bin categories.

## Implemented command boundaries

- `foal --help` is the current help surface and should use Foal/foal/foal.exe naming only.
- `foal version`, `foal --version`, and their `--json` forms are read-only and report shared release metadata: version, commit, Go runtime, and target platform.
- `foal status --json` is read-only and reports disk, OS, Foal command state, elapsed time, skipped items, and errors.
- `foal analyze --json <path>` is read-only and reports directory totals, top children, skipped entries, and elapsed time. Matching top-child names may be labeled `project_artifact_clue` only; analyze does not deep-scan for nested project artifacts and does not delete.
- `foal purge` is the independent Project artifact purge flow (not a Clean category). It requires one or more explicit user-supplied roots (never implied; multi-root only when each arg is valid; volume/system dangerous roots rejected). Default is dry-run recursive discovery of allowlisted rebuildable directories (`node_modules`, `target`, `dist`, `build`, `.build`, `.next`, `__pycache__`; exact final component). `--execute` rediscovers then permanently deletes matches only with per-run `--allow-permanent`; without it candidates are skipped and nothing is deleted. Permanent deletion is ordinary filesystem removal with reinstall/rebuild impact notice—not secure erasure, not elevation, not process stopping. Protection rules apply deny-only. Clean does not discover or delete project artifacts by default or via ordinary `--opt-in` catalog rows. Do not document Mole installer purge or implicit `purge_paths` as shipped.
- `foal clean --dry-run --json` previews conservative cleanup candidates and reports skipped-by-default Opportunity categories: idle `user_temp` entries; existence-observed `crash_dumps`, `windows_error_reporting`, exact-allowlist `explorer_thumbnail_cache` and `inet_cache`, plus `d3d_shader_cache`, `nvidia_dx_cache`, `amd_gpu_shader_caches`, and `intel_gpu_shader_cache` current-user roots; Chrome/Edge/Firefox `browser_cache` when the browser is idle before and after complete profile cache inspection; and idle Application cache categories `vscode_cache`, `cursor_cache`, `vscode_insiders_cache`, `vscodium_cache`, `windsurf_cache`, and `trae_cache` (VS Code-family editors under the Developer tools report category) when the owning editor is idle before and after exact allowlisted root inspection under the current user's standard Roaming AppData `Code`, `Cursor`, `Code - Insiders`, `VSCodium`, `Windsurf`, or `Trae` root respectively, plus `obsidian_cache` (a non-editor Electron app under the Applications report category) when Obsidian is idle before and after plain-Electron allowlisted root inspection under `%APPDATA%\obsidian`. Observed bytes are excluded from `Potential space`. The primary Clean TUI is category-first: entering Clean starts a catalog-derived eager path-free preview scan of every canonical default and opt-in cleanup category (no Review suggestion rows or external tool-query probes solely for those suggestions), defaults start selected but removable, permanent-action categories (`d3d_shader_cache`, `nvidia_dx_cache`, `amd_gpu_shader_caches`, `intel_gpu_shader_cache`, `browser_cache`, `vscode_cache`, `cursor_cache`, `vscode_insiders_cache`, `vscodium_cache`, `windsurf_cache`, `trae_cache`, package/build caches, `playwright-browsers`, `puppeteer-browsers`, `electron-cache`, `jetbrains-ide-caches`, `visual-studio-caches`, `grok-build-update-residue`, and `obsidian_cache`) start selected when measurable, other opt-ins start unselected, selection never restarts scanning, and confirmation is available only after every scannable category is terminal with a non-empty selection. Preview browsing, empty/unavailable/no-selection states write no History or detailed lists and call no cleanup adapter. Confirmed TUI execution freezes the exact selected category identifiers and permanent authorization when the selection discloses permanent actions, fresh-resolves candidates through shared Clean, reports observation-only progress outside Result JSON, records optional path-free TUI History provenance (`surface=tui`, `selection_mode=exact`, `selected_categories`), and preserves normal item-level result/history semantics; cancellation does not promise rollback. The first category-first slice has no retry or rescan action. Browser review is gated by Chrome/Edge running-application detection: running browsers are reported as Running application skips and unknown process state is a recoverable diagnostic. Application cache review uses generic application-idle-before-and-after-inspection with independent per-editor gates and the same fail-closed rules and never stops the application. The Recycle Bin is permanently excluded; developer-tool caches remain Review suggestions by default, or become Opt-in candidates when opted in via `--opt-in <dev-cache-name>` or `--opt-in dev-caches` or `--opt-in all` (including structured `playwright-browsers` versioned installations under the global Playwright root; `PLAYWRIGHT_BROWSERS_PATH=0` yields no candidate; MCP profiles and internal metadata are excluded); Application cache categories `vscode_cache`, `cursor_cache`, `vscode_insiders_cache`, `vscodium_cache`, `windsurf_cache`, and `trae_cache` are skipped by default and become Opt-in candidates via exact `--opt-in <name>`, `--opt-in dev-caches`, `--opt-in all`, or Clean TUI selection without implicitly selecting sibling editors; `obsidian_cache` is a non-editor Application cache under the Applications report category and becomes an Opt-in candidate via exact `--opt-in obsidian_cache`, `--opt-in app-caches`, `--opt-in all`, or Clean TUI selection, never via `dev-caches`; and administrator-only caches remain permission-boundary notices. `foal clean --execute` does not run opportunity discovery, browser/application running-application detection, or developer-tool cache probing by default, is the explicit confirmation path for fresh default candidates, and uses each category's catalog planned action (production permanent deletion currently covers `d3d_shader_cache`, `nvidia_dx_cache`, `amd_gpu_shader_caches`, `intel_gpu_shader_cache`, `browser_cache`, `vscode_cache`, `cursor_cache`, `vscode_insiders_cache`, `vscodium_cache`, `windsurf_cache`, `trae_cache`, package/build caches, `playwright-browsers`, `puppeteer-browsers`, `electron-cache`, `jetbrains-ide-caches`, `visual-studio-caches`, `grok-build-update-residue`, and `obsidian_cache`, which require CLI `--allow-permanent` or TUI confirmation authorization). When `--opt-in browser_cache` is used with `--execute`, browser running-application detection runs to skip active browsers; when `vscode_cache`, `cursor_cache`, `vscode_insiders_cache`, `vscodium_cache`, `windsurf_cache`, `trae_cache`, `obsidian_cache`, or other Application cache categories are opted in, detection and exact allowlisted root inspection run fresh with idle-before-and-after gating; when dev caches are opted in, their paths are resolved only from environment variables and default paths (no tool probing), fresh validation is performed immediately before deletion, and aggregate per-volume Recycle Bin capacity pre-checks are applied before any deletion for Recycle Bin work only. Structured developer-cache category `puppeteer-browsers` resolves from non-blank `PUPPETEER_CACHE_DIR` or the current user home `.cache\puppeteer` root, discovers only allowlisted product and Windows platform-version installation directories as independent Opt-in candidates (root and product parents are never candidates), uses shared-runtime policy without attributing Node/Python/Chrome/Firefox processes, never reads project Puppeteer configuration or runs Puppeteer/npx, and is included via `--opt-in puppeteer-browsers`, `--opt-in dev-caches`, `--opt-in all`, or Clean TUI selection. Developer-cache category `electron-cache` resolves from non-blank `electron_config_cache` or the current user's standard Windows `%LOCALAPPDATA%\electron\Cache` root (blank override falls back to default), treats only that whole root as a candidate, uses shared-runtime policy without attributing Node/Electron processes, never scans legacy `~\.electron` or project configuration, never runs Electron/npm/npx, and is included via `--opt-in electron-cache`, `--opt-in dev-caches`, `--opt-in all`, or Clean TUI selection. Developer-cache category `jetbrains-ide-caches` resolves only the current user's standard `%LOCALAPPDATA%\JetBrains` parent, discovers anchored 2020.1+ standard-layout IntelliJ-platform product-version roots (IntelliJ IDEA Ultimate/Community, PyCharm Professional/Community, WebStorm, PhpStorm, RubyMine, CLion, DataGrip, DataSpell, GoLand, RustRover, Aqua, MPS, Writerside, and Rider) as product-scoped scopes, reclaims only exact `caches` and `index` children (Rider also exact `resharper-host`) as independent Opt-in candidates, permanently excludes Local History and non-allowlisted system children, applies independent distinctive-process idle-before-and-after gates per logical product, never reads config/install/Toolbox/registry/CWD/projects/`idea.system.path`/properties/command lines/window titles, never invokes or stops JetBrains software, and is included via `--opt-in jetbrains-ide-caches`, `--opt-in dev-caches`, `--opt-in all`, or Clean TUI selection (unselected by default). Permanent deletion is ordinary filesystem removal only; do not document secure erasure or automatic elevation. Permanent-action categories start selected when safely measurable and remain independently removable. Developer-cache category `visual-studio-caches` resolves only the current user's standard %LOCALAPPDATA%\Microsoft\VisualStudio parent, discovers exact shared `Roslyn` and per-instance `ComponentModelCache` under anchored 14.0+ instance hives as independent Opt-in candidates, applies devenv idle-before-and-after gating independent of VS Code/Cursor, never wipes Settings/Extensions/ProgramData/solutions, never invokes or stops Visual Studio, and is included via `--opt-in visual-studio-caches`, `--opt-in dev-caches`, `--opt-in all`, or Clean TUI selection. Product-scoped CLI-agent category `grok-build-update-residue` resolves exact Windows updater `.old` backups under `$GROK_HOME\bin` with idle-before-and-after and recent-download fail-closed gates; it is included via `--opt-in grok-build-update-residue`, `--opt-in cli-agents`, `--opt-in all`, or Clean TUI selection, and is never a `dev-caches` member. The `app-caches` token expands Applications report-category application cache categories (currently `obsidian_cache`) in catalog order only; it owns no resolver, candidates, or deletion action, and `dev-caches` must not include it. The `cli-agents` token expands independently registered CLI-agent categories in catalog order only; it owns no resolver, candidates, or deletion action and does not imply all CLI-agent data is cache or safe to delete. Claude Code, Codex CLI, Antigravity CLI, and Gemini CLI remain research-only and are not catalog categories.
- User-defined Protection rules load from `%APPDATA%\Foal\protection.txt` or `FOAL_PROTECTION_FILE`, are deny-only, and protect an exact path plus its subtree. Suppress protected path-backed review-only discoveries before totals and all downstream surfaces; do not infer a Review suggestion path from command text.
- `foal history --json` reads operation history and reports sessions plus structured errors.
- `foal uninstall --json` previews installed applications. `--execute --select <name>` runs Official uninstaller invocation (quiet preferred, then interactive) for selected traditional desktop apps; dry-run remains the default. Process stopping requires a separate `--allow-stop-processes` flag and is off by default; running apps without it are skipped with a stable reason. After a successful uninstaller, Foal deletes only the revalidated subset of the Confirmed leftover path set (high-confidence Possible leftovers, frozen at confirmation time) via the Recycle Bin; Protection rules deny protected paths; a failed or canceled uninstaller never deletes leftovers and never falls back to Portable directory removal.

## Engineering constraints

- Preserve preview-first behavior and JSON-contract-first command surfaces.
- Every real delete path must be validated immediately before execution, even if it was already scanned or previewed.
- Protection rules can only remove candidates or path-backed review discoveries; they never authorize cleanup or expand the default candidate set.
- Tests should prioritize safety invariants and JSON contracts over human-output snapshots.
- Keep README, AGENTS, and plan docs aligned when changing product boundaries.
